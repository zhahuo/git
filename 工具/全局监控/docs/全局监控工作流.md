# 全局监控工作流

本工作流固化为“心跳 → 检测 → 移交 → 修复 → 规则沉淀 → 量化汇报”的闭环，用于按全局规则和全局工作流持续监控所有 Codex 会话。

## 流程

1. 心跳：自动化每 15 分钟触发一次检测模块（`rrule = FREQ=MINUTELY;INTERVAL=15`）；应用重启后的第一次心跳必须立即执行一次完整检测，检测模块维护最近完整检测时间标记，若发现长时间中断或应用重启则先补一次完整检测。
2. 检测：检测模块检查所有会话的目标状态、模块会话表、会话目录与职责一致性、自动化配置一致性和全局规则是否有更新。
3. 移交：发现问题时，用 `send_message_to_thread` 把问题及异常记录字段移交给执行模块。
4. 修复：执行模块查明原因并执行修复，修复后把结果发送给汇报模块。
5. 规则沉淀：修复完成后评估异常模式是否可复用、是否影响多会话、是否重复出现；值得沉淀则更新全局 AGENTS 和工作流技能。
6. 量化汇报：汇报模块向用户报告修复结果，并附上量化指标。

## 模块职责

- 检测模块：只负责检测与移交。检查目标状态、模块会话表、工作流执行、目录与职责一致性、自动化与全局规则一致性；发现问题时移交执行模块，不执行修复，不直接向用户汇报。
- 执行模块：接收检测模块移交的问题，查明原因并执行修复；完成后把修复结果发送给汇报模块；评估是否值得沉淀规则。
- 汇报模块：接收执行模块结果并向用户汇报，负责与用户交互；不做检测，不执行修复。

## 异常记录字段

每一条移交问题至少包含以下字段：

| 字段 | 说明 |
| --- | --- |
| 异常会话 ID | 发生异常的会话 ID |
| 异常类型 | 空转、偏离规则、目标卡住、配置冲突、未入库推送等 |
| 首次发现时间 | 检测到异常的时间 |
| 持续时长 | 异常持续的时间 |
| 原因 | 查明后的根因 |
| 修复动作 | 实际执行的修复步骤 |
| 修复时长 | 从移交到修复完成的时间 |
| 状态 | 已移交、修复中、已修复、已核验 |
| 验证结果 | 核验方式与结果 |

## 量化指标

- 监控会话数：每轮检测覆盖的会话数量。
- 异常数：本轮发现并移交的异常数量。
- 异常类型分布：按异常类型统计数量。
- 修复成功率：已修复异常数 / 已移交异常数。
- 平均修复时长：修复时长总和 / 已修复异常数。
- 规则沉淀次数：因异常模式更新全局规则或工作流技能的次数。

## 规则沉淀标准

满足以下任一标准即可沉淀进全局规则：

- 可复用：该流程或规则可复用于其他会话。
- 影响多会话：问题影响多个会话或全局配置。
- 重复出现：同类问题已出现多次。

不满足标准时，在执行结果中说明不沉淀的原因。

## 自我修复与优化

- 每轮心跳必须调用工具并追加写入 docs/检测记录.md；未写入记录即视为空转异常。
- 检测模块发现模块空转时先发送单步指令跟进；连续 3 次空转则升级给用户处理。
- 元监控：每轮检查上一轮检测记录是否存在、心跳间隔是否合理、自动化配置与工作流文档是否一致。
- 修复后评估是否沉淀规则，并把空转次数、重试次数、修复时长计入量化指标。
- 429 限流：等待后重试；手动触发与心跳重叠时合并为一轮。
- 汇报模块每轮核验检测记录，缺失即向检测模块发送单步指令，连续 3 次缺失升级给用户。
- 持续监控：检测模块每轮列出运行中的非监控会话，记录会话 ID、状态、最近活跃时间，运行期间持续跟进，结束后记录结束时间。
- 指令一律以目标形式下发：模块先创建目标，再调用工具执行，完成后 update_goal complete，未完成不得结束。
