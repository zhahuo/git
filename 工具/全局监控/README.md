# 全局会话监控项目

本项目用于按全局规则和全局工作流监控 Codex 中的所有会话，采用检测、执行、汇报三模块分工。

## 模块分工

- 检测模块：只负责检测，检查目标状态、模块会话表、会话是否按全局工作流执行，以及全局规则是否有更新；发现问题时移交给执行模块，不执行修复，不直接向用户汇报。
- 执行模块：接收检测模块移交的问题，查明原因并执行修复，修复后把结果发送给汇报模块。
- 汇报模块：接收执行模块的修复结果并向用户汇报，负责与用户交互；不做检测，不执行修复。

## 协作流程

1. 检测模块发现问题时，用 `send_message_to_thread` 把问题移交给执行模块。
2. 执行模块完成修复后，用 `send_message_to_thread` 把修复结果发送给汇报模块。
3. 汇报模块向用户汇报修复结果，并与用户交互。

## 自动化与规则同步

- 检测模块由每 5 分钟一次的心跳自动化触发（`rrule = FREQ=MINUTELY;INTERVAL=5`），应用重启后第一次心跳必须立即执行一次完整检测；手动触发与定时心跳重叠时合并为一轮。
- 触发条件为有对话进行时，自动启用全局监控模块并持续跟进；生效范围为 agent 中的所有对话。
- 自动化提示词与全局 AGENTS 中的全局监控规则保持一致：检测模块发现问题后移交给执行模块，执行模块修复后交给汇报模块汇报，不要结束监控目标。
- 全局规则有更新时，同步到全局 AGENTS 和工作流技能。
- 每轮心跳必须调用工具并追加写入 `docs/检测记录.md`，未留痕视为异常。
- 检测/执行/汇报模块会话更换或失败时，必须同步更新 docs/模块会话.md，模块表状态须与线程真实状态一致。

## 项目文件

- `README.md`：项目说明。
- `docs/模块会话.md`：模块会话表，记录模块名、会话 ID、状态和协作流程。
- `docs/检测记录.md`：每轮检测留痕记录。
