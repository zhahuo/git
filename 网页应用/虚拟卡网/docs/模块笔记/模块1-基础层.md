本模块只交付基础层：`src/lib/**`、`src/app/api/**`、根目录配置、`scripts/reset-db.mjs`、`API.md`。未创建任何页面（`page.tsx` / `layout.tsx`）、未创建 `public/` 资源、未运行 `pnpm build`。

## 2. 交付内容

### 2.3 基础层关键实现

- `src/lib/orders.ts`：
  - `createOrder`：服务端读取商品价格重新计价；校验商品上架状态与可用库存；库存不足返回 409 禁止下单。
  - `payOrder`：`BEGIN IMMEDIATE` 事务内校验订单与余额、锁定卡密、扣余额并写 `balance_logs`、写 `payments`、更新销量、订单置为 `delivered`。库存不足时先把订单置为 `cancelled` 并提交，再返回 409。
  - `loadOrder` / `orderWithCards` / `listOrders`：详情、发货卡密填充与分页列表。
  - `cancelOrder` / `deliverOrder`：供管理端状态操作（取消仅限 pending；发货仅限 paid）。
- `src/lib/auth.ts` 新增 `requireUser` / `requireAdmin`，管理端统一走 `401`/`403`。
- `src/lib/api.ts` 新增 `handleError` / `runRoute`，路由层统一捕获 `ApiError` 输出 JSON 错误。
- `src/lib/balance.ts`：余额流水查询与演示充值（含事务与 `balance_logs`）。
- `src/lib/products.ts`：管理端商品行查询与库存数联表 SQL。
- 商品删除保护：已有 `sold` 卡密的商品禁止删除（409），避免级联删除订单发货记录；建议下架。

### 2.4 类型修复

`node:sqlite` 的 `StatementSync.get/all` 返回 `Record<string, SQLOutputValue>`，直接 `as T` 无法通过 strict 检查。已改为 `as unknown as T`，并把 `orders.ts` 的查询行抽成 `ProductRow` / `OrderRow` 接口 + 行映射函数，避免 `unknown` 属性外泄。

修复范围：

- `src/lib/orders.ts`（商品行、订单行、明细、卡密、用户行）
- `src/app/api/auth/register/route.ts`
- `src/app/api/categories/route.ts`
- `src/app/api/products/route.ts`
- `src/app/api/products/[id]/route.ts`

- 商品删除保护：已有售出卡密的商品删除返回 409。
- 数据库核验：`cards` 中 `sold` 且 `order_item_id` 为空的记录为 0，不存在重复 `content` 的已售卡密，证明同一卡密只发放一次。
- `pnpm typecheck` 通过。

## 5. 遗留问题

- 当前支付流程把 `pending` 直接推进到 `delivered`，`paid` 为数据表保留的中间状态，管理端「发货」仅作用于 `paid` 订单；未来若引入人工收款流程可复用 `deliverOrder`。
- 商品删除会级联删除该商品全部卡密（schema 层 CASCADE），本模块已用 409 保护“已有售出卡密的商品”，防止订单追溯丢失。

## 6. 续作：外部发卡记录查询接口

### 6.1 新增内容

- 新增 `GET /api/admin/integration/claims`（仅 admin 可访问），用于闲鱼自动发货对接后的对账。
- 查询 `integration_claims` 表并 `LEFT JOIN products` 返回 `product_name`，字段含 `id`、`claim_no`、`external_order_no`、`product_id`、`product_name`、`quantity`、`card_ids`、`created_at`，按 `created_at DESC, id DESC` 排序。
- 支持分页：`limit`（默认 50，最大 200）、`offset`（默认 0），返回 `{ claims, total }`。
- 支持筛选：`product_id`（精确）、`external_order_no`（模糊 LIKE）、`created_from` / `created_to`（UTC 时间范围，支持 `YYYY-MM-DD` 自动补时分秒）。
- `API.md` 已补充 5.16 节接口文档（查询参数、响应示例、curl 示例）。

### 6.2 验证结果

- `pnpm typecheck` 通过。
- dev 服务器（3000）实测通过：
  - 通过 `POST /api/integration/cards/claim`（Bearer token）创建 2 条测试发卡记录；
  - `GET /api/admin/integration/claims` 返回全部记录且字段完整、`product_name` 正确联表、按时间倒序；
  - `product_id`、`external_order_no` 模糊、`created_from` 筛选均命中正确数量；
  - `limit=1&offset=0/1` 分页返回不同记录且 `total` 不变；
  - 未登录 401、普通用户 403。
- 验证后已停止 dev 服务器，并删除测试发卡记录、把对应卡密恢复为 `available`、销量恢复为 0，数据库回到种子数据状态。
