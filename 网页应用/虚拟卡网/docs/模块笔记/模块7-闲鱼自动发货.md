# 模块7 闲鱼自动发货（发卡桥接）实现笔记

## 1. 职责范围

本模块交付闲鱼侧到卡网侧的「发卡桥接」：接收模块6 后端转发的订单触发事件
（消息 / 拍下 / 付款），按闲鱼商品映射调用卡网
`POST /api/integration/cards/claim` 领卡，再把卡密按模板发送给买家。

只新建/修改以下文件：

- `integrations/xianyu/bridge/**`（映射配置、桥接库、HTTP 服务、CLI、日志、测试）
- `docs/模块笔记/模块7-闲鱼自动发货.md`

未触碰 `src/**`、`API.md`、`README.md`、`package.json`。模块6 的账号/自动回复
核心文件部署在外部仓库（GuDong2003/xianyu-auto-reply-fix），本仓库内没有该
模块文件，因此没有改动。

## 2. 接入方式

采用「独立适配服务」：`integrations/xianyu/bridge/server.mjs` 提供
`POST /trigger`（别名 `POST /api/trigger`）与 `GET /health`，模块6 在
「消息、拍下、付款」节点把订单事件转发过来；也可以直接调用
`deliver.mjs --event '{}'`，适合无法回调 HTTP 的场景。

触发事件格式：

```json
{
  "external_order_no": "XIANYU-20260816-001",
  "item_id": "123456789012",
  "buyer_id": "taobao_123",
  "session_id": "可选，模块6 会话标识",
  "quantity": 1,
  "trigger": "message | order_created | order_paid"
}
```

`external_order_no` 每次必须传，作为幂等键；`item_id` 与 `title` 至少传一个。
服务默认监听 `127.0.0.1:8787`，生产建议设置 `BRIDGE_TRIGGER_TOKEN` 并让模块6
携带 `Authorization: Bearer <token>`。

## 3. 商品映射配置

`config/mapping.json` 支持两种匹配：

- `items[]`：按闲鱼 `item_id` 精确匹配，可配置 `product_id`、`quantity`（一次发
  多张卡密）、`enabled`；
- `aliases[]`：按标题关键词 `title_contains` 兜底匹配，适合模块6 只提供标题的
  场景。

示例：

```json
{
  "items": [
    { "item_id": "123456789012", "title": "Steam 充值卡 50 元 秒发", "product_id": 1, "quantity": 1, "enabled": true }
  ],
  "aliases": [
    { "title_contains": "Steam 50", "product_id": 1, "quantity": 1, "enabled": true }
  ]
}
```

仓库内置的 `mapping.json` 为示例且 `enabled: false`，上线前必须替换为真实闲鱼
商品并开启。未匹配到映射时返回 `mapping_missing`，只记录日志并通知管理员，
不调用发卡接口。

## 4. 发卡调用

`lib/card-client.mjs` 调用卡网领卡接口：

```text
POST {cardApi.baseUrl}/api/integration/cards/claim
Authorization: Bearer ${INTEGRATION_API_TOKEN}
{ "product_id": 1, "quantity": 2, "external_order_no": "XIANYU-20260816-001" }
```

令牌从环境变量 `INTEGRATION_API_TOKEN`（可配置 `cardApi.tokenEnv`）读取，不写入
配置文件。`external_order_no` 始终传递，卡网侧的 `integration_claims` 唯一索引
保证重复调用返回 409，不会多发。

## 5. 多节点触发与去重

消息、拍下、付款三个节点都可以触发发货，去重分两层：

1. 本地状态：`runtime/bridge.db` 以 `external_order_no` 为主键记录每次发货状态
   （`sent` / `already_claimed` / `business_error` / `failed` 等）；已成功发货的
   订单再次触发直接返回 `already_delivered`，不再调卡网。
2. 卡网幂等：即使本地状态丢失（如换机器），卡网接口仍会对同一
   `external_order_no` 返回 409「该外部订单已发过卡」，桥接记录日志并返回
   `already_claimed`，不再发送卡密。

进程内按订单号加锁，同一订单的并发触发串行处理。

## 6. 消息模板

`config/settings.json -> message` 支持两种模式：

- `sendMode: "merged"`：多张卡密合并为一条消息发送，支持
  `{cards_lines}`、`{claim_no}`、`{product_name}`、`{external_order_no}`、
  `{quantity}` 等占位符；
- `sendMode: "per_card"`：每张卡密单独一条消息，额外支持 `{content}`、
  `{index}`、`{total}`。

发送目标由 `sender.http.url` 指定，桥接向该地址 POST 一条
`type: "card_delivery"` 的 JSON（含 `content`、`external_order_no`、`item_id`、
`buyer_id`、`session_id`、`trigger`、`claim_no` 相关字段由模板内嵌在 `content`），
由模块6 后端负责真正回给闲鱼买家；未配置时消息只写 JSONL 日志，便于联调。

## 7. 失败兜底

- 网络错误与 5xx/429：自动重试，默认最多重试 3 次（共 4 次尝试），指数退避
  （500ms 起步、3s 封顶）；重试耗尽后标记 `failed` 并通知管理员。
- 409「已发过卡」：记录日志（含原 `claim_no`），标记 `already_claimed`，不发
  消息。
- 409「库存不足 / 商品已下架」：向买家回复「库存不足，请联系客服」（可通过
  `message.businessErrorReply` 修改），并通知管理员，标记 `business_error`。
- 401 / 400 / 404：标记 `failed` 并通知管理员，不发买家消息（配置或映射问题）。
- 已领卡成功但发送消息失败：本地保留 `claim_no` 与卡密内容，状态
  `claimed_send_failed`，下次触发自动补发消息，不重复领卡。
- 日志：`logs/bridge-YYYY-MM-DD.jsonl` 记录 `claim_no`、闲鱼订单号、卡网商品、
  数量、结果与错误，方便对账。

## 8. 测试结果

环境：捆绑 Node v24.19.0，PowerShell；测试不依赖额外 npm 包。

### 8.1 mock 测试（默认模式）

`node integrations/xianyu/bridge/test/test-bridge.mjs`，共 24 项全部通过：

- 200 领卡成功、合并消息发送、本地状态 `sent`；
- 401 未授权标记失败、不发送买家消息、通知管理员；
- 409 重复订单（模拟本地状态丢失）返回 `already_claimed`，第二次请求仍到达卡网
  并命中幂等，不再发送；
- 409 库存不足回复固定文案并通知管理员；
- 临时 503 重试 2 次后成功（共 3 次尝试）；
- 映射缺失返回 `mapping_missing` 并通知管理员；
- 逐条模式按卡密数发送多条；
- HTTP `POST /trigger`、`GET /health`、触发端点鉴权 401。

### 8.2 真实卡网接口验证

先在 3007 端口启动卡网（`pnpm dev`，`NEXT_DIST_DIR=.next-m7`），设置
`INTEGRATION_API_TOKEN=test-token` 后运行：

```powershell
node integrations/xianyu/bridge/test/test-bridge.mjs --real
```

结果 5 项全部通过：健康检查 200、错误令牌 401、领卡 200、重复
`external_order_no` 返回 409 已发过卡、库存不足返回 409 且桥接识别为
`business_error`。验证产生的 `tsconfig.json` 自动改动（Next 追加
`.next-m7/types/**/*.ts`）已恢复为原状。

## 10. 遗留问题

- 模块6 后端的「发送消息给买家」接口契约尚未最终确认，目前桥接通过可配置的
  `sender.http.url` 回调，模块6 侧需要把回调里的 `content` 真正发送到对应
  `session_id` / `buyer_id`；若模块6 提供其他协议，只需改 `lib/sender.mjs`。
- 本地去重状态存在桥接服务自身的 SQLite（`runtime/bridge.db`），多实例部署时需
  共享状态或完全依赖卡网幂等；卡网幂等始终兜底，不会多发，但消息补发可能
  需要管理员介入。
- `business_error` 与 `mapping_missing` 按终态处理，库存补货后不会自动重试同一
  订单，需人工处理或清理本地状态后重新触发。
- 卡网 `claim` 接口的 404/400/401 在桥接中合并为 `failed`，未向买家发送解释性
  消息，仅通知管理员。
- 真实发送依赖模块6 部署的闲鱼会话，本机仅验证了桥接到卡网接口的链路，未验证
  闲鱼端实际收发。
