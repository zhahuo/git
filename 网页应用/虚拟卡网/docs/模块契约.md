# 虚拟卡网模块契约

本文件是「虚拟卡网」项目各模块会话的共同约定。每个模块在独立会话中执行，只修改自己拥有的文件，其他文件一律只读。工作目录固定为 `C:\Users\袁\Documents\ChatGPT\虚拟卡网`。

## 1. 项目目标

做一个完整可用的中文虚拟卡密商城：

- 用户浏览商品、加入购物车、下单、模拟支付后自动获取卡密。
- 管理员后台管理商品、分类、卡密库存、订单和销售统计。
- Next.js（App Router）+ TypeScript + Tailwind CSS + SQLite（`node:sqlite`），前后端一体，本地低成本运行。

## 2. 技术约定

- 使用捆绑运行时：Node 24（`C:\Users\袁\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe`）、pnpm（`...\dependencies\bin\fallback\pnpm.cmd`）。
- 数据库文件：`data/app.db`，首次访问自动建表并写入种子数据；重置命令 `pnpm db:reset`。
- 不引入额外原生数据库依赖，使用 `node:sqlite`；SQL 全部写在 `src/lib/schema.sql`。
- 金额统一用整数「分」存储；时间统一存 UTC，展示用 Asia/Shanghai。
- 中文界面；首页第一屏就是可用商城，不做落地页；响应式；桌面/移动端文字不重叠。
- 图标使用 lucide-react；商品封面使用 `public/covers/*.svg` 本地矢量资源。
- 只有模块5执行 `pnpm build`；其他模块验证用 `pnpm typecheck` 或启动 dev（端口冲突时用 3001）。
- 并行模块各自验证 dev 时使用独立端口与构建目录：模块2 用 `NEXT_DIST_DIR=.next-m2` + 端口 3101，模块3 用 `.next-m3` + 3102，模块4 用 `.next-m4` + 3103；验证后必须停止 dev 服务器。

## 3. 数据表

`users`（角色 user/admin、余额分）、`sessions`、`categories`、`products`（含售价、上下架、库存预警阈值、销量）、`orders`、`order_items`、`cards`（available/sold，唯一键 `(product_id, content)`）、`payments`、`balance_logs`。

订单状态机：`pending`（待支付）→ `paid`（已支付）→ `delivered`（已发货）；`pending` 可 `cancelled`。模拟支付成功后自动绑定卡密并置为 `delivered`；同一卡密只发放一次；卡密不足时禁止下单。

## 4. API 契约（模块1输出 `API.md` 为权威文档）

公共：

- `GET /api/health`
- `GET /api/products?q=&category=&sort=`；`GET /api/products/[id]`
- `GET /api/categories`
- `POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`
- `POST /api/orders`（创建订单，服务端计价与校验库存）、`GET /api/orders`、`GET /api/orders/[id]`
- `POST /api/payments/[orderId]`（`method: mock | balance`，支付成功即发货）
- `GET /api/balance`、`POST /api/balance/recharge`（演示充值）

管理端（仅 admin/admin123）：

- `GET/POST /api/admin/products`；`PATCH/DELETE /api/admin/products/[id]`
- `GET/POST /api/admin/categories`；`PUT/DELETE /api/admin/categories/[id]`
- `GET/POST /api/admin/cards`（批量导入）；`DELETE /api/admin/cards/[id]`
- `GET /api/admin/orders`；`PATCH /api/admin/orders/[id]`（cancel/deliver）
- `GET /api/admin/stats`（今日/累计销量、订单数、低库存预警、分类销售、最近订单）

会话：httpOnly cookie `vc_session`，30 天有效。角色权限：普通用户只能访问前台与个人中心，admin 可访问后台。

## 6. 验收标准

- 核心链路：浏览 → 详情 → 加购 → 结算 → 登录 → 下单 → 模拟支付 → 自动发货并展示卡密 → 复制卡密。
- 边界：同一卡密只发一次；卡密不足时下单被拒绝；余额支付时余额不足被拒绝；待支付订单可取消。
- 后台：商品/分类 CRUD、上下架、卡密批量导入与余量预警、订单状态管理、今日/累计统计。
- 交付：`pnpm build` 通过；桌面与移动端截图检查；README 含启动方式、默认账号、VPS/Docker 部署说明；按 desktop-codex-archive 规范归档到桌面 Codex「虚拟卡网」。
